1. **Identify** novel attack vectors before they're exploited in production
2. **Generate** high-fidelity attack simulations at scale using cutting-edge generative AI
3. **Defend** with ML models that continuously improve against adversarial pressure

## 4. Key Novel Findings

### Finding 1: Multi-Hop CNP Relay Attack (ATK-002)

Autonomous AI purchasing agents can bypass velocity controls by distributing transactions across 100+ proxy IPs with geo-consistent rotation. The 52% bypass rate demonstrates the vulnerability of current velocity-based defenses.

**Attack Flow:**

```
AI Agent -> Proxy Pool (100+ IPs) -> Geo-Rotation -> Merchant -> Payment Gateway
                                      (City-level consistency)
```

**Impact:** Traditional IP-based velocity rules are insufficient against distributed autonomous agents. Recommendation: Implement graph-based velocity analysis across device/IP/card clusters.

### Finding 2: LLM Payment Gateway Injection (ATK-003)

Prompt injection into merchant AI assistants can manipulate transaction routing and extract card data through side-channels in natural language responses. This represents a novel attack surface in conversational commerce.

**Attack Mechanism:**

```
User Input -> Merchant AI Assistant -> Hidden Prompt Injection ->
  -> Transaction Data Exfiltration via NL Response -> Card Data Leaked
```

**Impact:** Conversational commerce platforms using LLMs are vulnerable to data exfiltration. Recommendation: Implement input sanitization and output filtering for payment-related AI assistants.

### Finding 3: Synthetic Identity Orchestration (ATK-001)

LLM-generated personas with coordinated credit histories can pass KYC checks across multiple institutions, with 92% fidelity making them nearly indistinguishable from legitimate accounts.

**Generation Pipeline:**

```
LLM Persona Generation -> SSN/DOB Synthesis -> Credit History Fabrication ->
  -> Cross-Institution Consistency Check -> KYC Evasion (92% success)
```

**Impact:** Current KYC processes rely heavily on data consistency checks that can be systematically gamed. Recommendation: Implement behavioral biometrics and transaction pattern analysis for identity verification.

The Tabular Denoising Diffusion Probabilistic Model (TabDDPM) generates synthetic fraud transactions with strong privacy guarantees:

- **Architecture:** NCSN (Noise Conditioned Score Network) with Gaussian diffusion
- **Tabular Handling:** Optimized for mixed categorical/continuous features
- **Privacy:** Differential privacy through noise scheduling
- **Fidelity:** Preserves correlation structure between transaction features
- **Conditional Generation:** Class-conditional sampling for targeted fraud synthesis

```python
# TabDDPM generation pipeline
generator = TabDDPMGenerator(
    n_features=45,
    n_categorical=12,
    n_continuous=33,
    num_timesteps=1000,
    beta_schedule="cosine"
)
synthetic_fraud = generator.sample(n_samples=10000, label=1)
```

### 5.7 Constraint-Guided Tabular Diffusion with Hard Invariants (`src/red_team/constrained_diffusion.py`)

Extends TabDDPM with differentiable constraint penalties during reverse diffusion:

- **Constraint-Augmented Reverse Step:** x_0_hat = x_t - sigma_t * (epsilon_theta + gamma * grad_C(x_t))
- **6 Hard Constraints:**
  - `AmountRange` — Transaction amounts within [min, max] bounds
  - `IBANChecksum` — Mod-97 checksum validation (ISO 13616)
  - `CurrencyCode` — Valid ISO 4217 currency codes (50 codes)
  - `TimeSequence` — Strictly increasing transaction timestamps
  - `CreditLimit` — Cumulative amounts within credit limits
  - `MerchantCategory` — Valid MCC code assignments (10 MCCs)
- **Benford's Law enforcement** as post-hoc digit distribution correction
- **ConstraintViolationReporter** with per-constraint satisfaction rates
- **Dashboard:** ConstraintPanel with satisfaction rates, violation breakdown, generate button

### 5.8 Privacy-Preserving Federated Learning with Differential Privacy (`src/blue_team/federated_learning.py`)

FedAvg across a simulated multi-bank ecosystem (10 banks) with formal privacy guarantees:

- **FedAvg Aggregation:** Weighted average across bank models based on local dataset sizes
- **DP-SGD:** Gradient clipping + Gaussian noise injection
  - g_tilde = (1/N) * (sum(Clip(g_i, C)) + N(0, sigma^2 * C^2 * I))
- **Privacy budget tracking** with advanced composition theorem (Rényi DP moments accountant)
- **Per-bank model isolation** with secure aggregation protocol
- **FederatedSimulation** with red team attack injection at specific rounds
- **Dashboard:** FederatedLearningPanel with privacy budget (epsilon), per-bank status, DP vs No-DP comparison chart

### 5.9 Game-Theoretic Stackelberg Equilibrium Solver (`src/blue_team/stackelberg_solver.py`)

Bi-Level Security Game modeling adversarial dynamics between Blue Team (defender) and Red Team (attacker):

- **Stackelberg Equilibrium:**
  - max_theta_Blue E[R_Blue(theta_Blue, theta_Red*)]
  - s.t. theta_Red* = argmax_theta_Red R_Red(theta_Blue, theta_Red)
- **Leader:** Blue Team commits to defense strategy first
- **Follower:** Red Team best-responds to Blue's committed strategy
- **EquilibriumAnalyzer** with convergence rate, stability scoring, and payoff trend
- **SecurityGameSimulator** with Monte Carlo game simulation and Nash fallback
- **Dashboard:** GameTheoryPanel with payoff matrix heatmap, convergence chart, equilibrium status badge

### 5.10 Zero-Knowledge Proof (zk-SNARKs) Verification (`src/blue_team/zkp_verification.py`)

Groth16-style zero-knowledge proofs for privacy-preserving fraud detection verification:

- **Proof System:** Groth16 (preprocessing SNARK with constant-size proofs)
- **Circuits:** R1CS constraint systems for fraud detection logic verification
- **Pedersen Commitments** for model weight hiding (hiding model parameters while proving correctness)
- **Merchant Verification Certificates:** ZK proofs that transactions passed rigorous AI fraud checks without exposing proprietary ML feature weights or private customer data
- **CircomExporter** for generating .circom circuit files
- **Dashboard:** ZKPPanel with proof status, circuit visualization, certificate display, merchant explanation
